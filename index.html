Abstract

A tight loop between neural intuition and symbolic truth.

Autonomous agents on edge hardware cannot afford the compute footprint of frontier LLMs, yet they still need dependable task-planning. VOLTS closes the gap.

What the paper shows

A single forward pass with a fine-tuned 4-bit Llama 3.1 8B emits syntactically and semantically valid PDDL plans, while respecting tight memory and latency budgets. On 2,000 IPC problems across Blocksworld, Logistics, DriverLog and Rover, VOLTS returns valid plans for 76.4% of tasks, averaging 1.08× the length of Fast Downward solutions, far ahead of GPT-4o (7.2% validity) and a fine-tuned baseline without in-loop validation (0.13%).

Three ideas

Action tokens. Real-time validation. Parallel branching.

VOLTS rests on three tightly coupled choices that together turn an SLM into a reliable on-device planner.

01

Action-token fine-tuning

The SLM is fine-tuned on a custom vocabulary where every token encodes a complete grounded action. This gives the model strong task heuristics without expanding its size, and makes per-token validation possible.

02

Real-time validator

A lightweight symbolic module checks each candidate token against the current state during decoding. Any plan emitted by VOLTS contains no hallucinated or infeasible actions by construction.

03

Parallel branching search

When several validated actions look promising, VOLTS explores them in parallel branches within the same forward pass, preserving single-pass efficiency while widening search, gated by a branching ratio β and a cap kmax.

Method

How VOLTS works, step by step.

Three animated views unpack the proposed inference loop. Each runs continuously, so you can watch the algorithm unfold.

Step 1 · Vocabulary

One token per grounded action.

Standard sub-word tokenization fragments PDDL actions across many tokens, making mid-generation validation impossible. VOLTS resizes the embedding layer and LM head over a custom vocabulary where each PDDL action is a single, atomic token.

Result: every emitted token is a complete, validatable action, and the validator can fire after every step.

Tokenization comparison
Step 2 · Validation

A symbolic check, fast enough to live inside decoding.

A custom Python PDDL grounder checks each candidate action token against the current symbolic state at every decoding step. Invalid candidates are filtered before they can extend a branch, eliminating hallucinated or infeasible actions by construction.

The validator is fast enough that it runs inside the generation loop, not as a post-hoc filter.

Token-level validation flow
Step 3 · Search

Branch when alternatives are close, prune when they aren't.

For every branch, VOLTS keeps the highest-scoring valid action as the primary continuation. Other valid actions whose logits are within a ratio β = 1.15 of the leader spawn new branches, up to a hard cap kmax = 4.

All branches are processed in a single batched forward pass, so search widens without iterative LLM calls.

Logit-guided parallel branching

The VOLTS inference loop

1

Batch candidate generation

All active branches go into the SLM as a single batch I. One forward pass yields a logit vector li per branch.

2

Per-branch validation

For each branch, candidate tokens are evaluated by the validator against the current state si. Only valid actions enter Avalid.

3

Extend or prune

If Avalid is empty, the branch is pruned. Otherwise, the highest-logit valid action extends the branch; goal-reaching branches return immediately.

4

Dynamic branch spawning

For every other valid action whose score is within ratio β of the leader, spawn a new branch, provided |B| < kmax.

5

Loop

Continue until a plan is returned, all branches are pruned, or Tmax is hit. All explored paths are valid by construction.

Results

An SLM that beats frontier LLMs on validity.

Evaluated on 2,000 problems across Blocksworld, Logistics, DriverLog and Rover, VOLTS dominates every neural baseline, including a frontier reasoning model and an identically fine-tuned ablation.
